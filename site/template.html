How much accuracy do you really lose when you quantize?

Published benchmarks rarely test quantized GGUF variants head-to-head. This project measures the real accuracy cost across quantization levels — same hardware, same harness, same prompts. Only the quant changes.

About v1 — and why everything changed
The first version of this project used lm-evaluation-harness with ARC-Challenge, IFEval, GSM8K and HumanEval. These were dropped for two reasons: saturation (modern 9B+ models score so tightly at the ceiling that quant differences disappear into noise) and format issues (HumanEval's completion format is incompatible with instruct models; IFEval scores were polluted by <think> tags). A first attempt at a new suite added BBEH-mini, but it takes days per model on consumer hardware — impractical for systematic quant comparisons. The v2 suite was designed around one constraint: fast, reliable, non-saturated, with fully deterministic scoring (no LLM judge). Raw results from v1 are preserved in LEGACY.md on GitHub.

v2 benchmark suite — current scope

All evaluations run through inspect_ai with fully deterministic scoring — no LLM judge. The three benchmarks were chosen because they remain discriminating on modern models and complete in a reasonable time on consumer hardware. These results are not directly comparable to official leaderboard scores: inference runs under consumer hardware constraints (q4_0 KV cache, 32k context).

01Pick your use case, not your quant

Code, reasoning and tool use degrade differently under quantization. The three benchmarks were chosen because they are hard to saturate, fast to run on consumer hardware, and cover complementary capability axes.

BigCodeBench

Code Generation

Diverse programming tasks across real-world libraries. Much harder than HumanEval — measures practical coding ability. Scored by unit test execution, fully deterministic.

MUSR

Assistant Reasoning

Multi-step reasoning over long narrative context — mystery stories, object tracking, team assignments. Mirrors what a chatbot or support assistant has to do: track several clues or entities across a conversation or document before answering. Stays well below saturation on modern models.

BFCL

Function Calling

Berkeley Function-Calling Leaderboard — tests the ability to generate correct tool calls given a function spec. Scored by AST matching. Directly measures agentic / tool-use capability.

Design principle: each benchmark covers a different capability axis, uses deterministic scoring (no LLM judge), fast enough to run systematically on consumer hardware, and discriminates between modern 9B–35B models without saturating.

Mixture of Experts

MoE

MoE models activate only a fraction of their parameters per token, so quantization noise affects a much smaller slice of the network at inference time. This makes them dramatically more resilient across the quant range.

Dense Models

Dense

Dense models show a clear performance cliff at aggressive quants. Smaller models are hit hardest; larger dense models tolerate more noise. The pattern is consistent across benchmarks: Q3 is the practical floor for most dense models.

04Methodology

Reproducibility matters. All scripts, parameters, and raw results are on GitHub.

Evaluation harness

All benchmarks run through Inspect AI (UK AISI / inspect_evals), with models served locally via llama-server. Scoring is fully deterministic — no LLM judge.

BigCodeBench

Practical code generation across real-world libraries. Scored by unit test execution (pass@1, complete split). Full benchmark — no limit.

MUSR

Multi-Step Soft Reasoning — narrative logic (mystery, object tracking, team allocation). MCQ format, accuracy scoring. Full dataset (~750 questions). Chosen for staying well below saturation on modern models.

BFCL

Berkeley Function-Calling Leaderboard — tests structured tool-call generation. Scored by AST matching (deterministic). Run with --limit 1000 --seed 42 for reproducibility across models.

KV cache & hardware

All models tested with q4_0 KV cache (K and V), reflecting real consumer usage. Hardware: 2× RTX 3060 12 GB for larger models, GTX 1070 8 GB for small quants. Context: up to 32k tokens depending on model.
