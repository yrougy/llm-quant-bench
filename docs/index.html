How much accuracy do you really lose when you quantize?

Published benchmarks rarely test quantized GGUF variants head-to-head. This project measures the real accuracy cost across quantization levels — same hardware, same harness, same prompts. Only the quant changes.

01Pick your use case, not your quant

A Q3 that's "bad at code" can be an excellent agent. Each benchmark measures a different capability, and they don't degrade at the same rate. Your quant floor depends on what you're doing with the model.

ARC-Challenge

Comprehension & Chat

Science QA with distractors. Measures whether the model understands what you're saying and resists confusion.

Quantization resilience
IFEval

Agents & Tool Use

Strict instruction following. Measures if the model obeys formatting constraints exactly — critical for agentic workflows.

Quantization resilience
GSM8K

Reasoning

Multi-step arithmetic. Tests chain-of-thought ability and whether the model can hold intermediate results without losing track.

Quantization resilience
HumanEval

Code Generation

Python pass@1. Tests whether generated code actually runs. First benchmark to collapse under quantization. Practical floor: ≥ 65% — below that, structurally broken code becomes too frequent to be useful.

Quantization resilience
HumanEval+

Code Robustness

Same problems, 80× more test cases. Catches false positives where code passes by luck. Practical floor: ≥ 60%. Watch the gap with HumanEval — a large spread means the model handles basics but collapses on edge cases.

Quantization resilience
Key insight: If your use case is running an agent (Hermes Agent, Picoclaw…), you need IFEval and ARC to hold — and they do, even at Q3. For code, aim for ≥ 65% HumanEval+ as a practical floor; below that, edge cases break too often. The right quant depends on what you're doing, not on a single leaderboard score.

03Dense vs MoE: quantization resilience

MoE architectures handle aggressive quantization dramatically better than dense models. Switch benchmarks to see how each capability degrades differently.

↳ Observation

Mixture of Experts

MoE

The Qwen 3.6 A35B holds 95% ARC even at IQ1_M — the most aggressive quant tested. Only 3B parameters activate per pass, so quantization noise affects a smaller fraction of the network at inference time.

Dense Models

Dense

Smaller dense models show a clear cliff below Q3. The 4B collapses to 34% ARC at IQ2_XXS — near-total failure. The 27B barely moves even at IQ2_XXS; at that scale, quantization noise barely registers on ARC. For the 4B and 9B, Q3 is the real floor.

04Methodology

Reproducibility matters. All scripts, parameters, and raw results are on GitHub.

Evaluation harness

All tests run through lm-evaluation-harness by EleutherAI with models served via llama-server from llama.cpp.

ARC-Challenge variant

Standard ARC relies on token probabilities that llama.cpp doesn't expose correctly. We use arc_challenge_chat instead — less granular but reliable with this inference engine.

IFEval & thinking models

Models with <think> tags can break IFEval's word-count scripts. Thinking is disabled via chat-template-kwargs to get accurate measurements.

GSM8K parsing

Instruct models produce verbose answers that break exact-match scoring. Correct tokenizer and chat template configuration is required to get meaningful results.

KV cache

All models tested with q4_0 KV cache for both K and V, which reflects real consumer usage rather than FP16 cache that wouldn't fit in VRAM.

Hardware

Personal hardware — two consumer machines: one with 2× RTX 3060 12 GB (larger models, multi-GPU split), one with a GTX 1070 8 GB (smallest quants). The same kind of setup you're likely running. Context: 16k–65k tokens.
